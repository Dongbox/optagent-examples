# MG Model Stage

This directory is the formal replacement point for the original APS model phase:

```text
program/model/
```

Instead of calling APS `Agent.run()`, `program/main.py` calls
`examples.mg.program.model.reports.run_production_case(...)` for the model phase.

Input data is read from the SQLite `i_*` / `t_*` tables generated by the
preprocess stage. Output is written to `o_mg_optagent_*` tables, with optional
compatibility tables for downstream postprocess adapters.

## Runtime Flow

```text
program/main.py
  -> reports.run_production_case(db_path)
     -> preprocess.data.load_mg_case(...)
     -> reports.build_search_replacement_report(...)
        -> search.solve_mg_sequence(...)
           -> model.build_mg_program(...)
           -> OptAgent Orchestrator.run(...)
     -> postprocess.write_production_output_tables(...)
     -> optional postprocess.write_legacy_compatibility_tables(...)
```

Production `main.py` intentionally accepts only one SQLite path. Search tuning,
scoped cases, dry runs, JSON summaries, and parity/structured diagnostics are
Python APIs for migration validation rather than production CLI flags.

## Files

- `model.py`: builds the OptAgent program. It declares the `sequence_var`, wires
  `rules.score_sequence_external(...)` into the blackbox objective, and attaches
  structured adjacent-edge metadata for diagnostics and future exact lowering.
- `search.py`: owns solving only. It maps MG search modes (`tabu`, `polish`,
  `evolutionary`) to OptAgent `OrchestratorConfig`, runs mode/seed attempts, and
  extracts the best final sequence plus solver traces.
- `reports.py`: owns migration and output reporting. It adds APS parity context,
  structured-edge diagnostics, production payload assembly, and SQLite
  `o_mg_optagent_*` writes around the actual search result.
- `rules.py`: owns MG scoring semantics. The current objective remains
  blackbox-scored because active-prefix, campaign, and follower-window behavior
  are stateful.

## Search Modes

- `tabu`: low-overhead local search around the warm-start sequence from
  `t_process_output`.
- `polish`: tabu intensification followed by a short annealing/LNS diversify
  phase for repairing local defects.
- `evolutionary`: population search with sequence mutations and light tabu
  polishing, closest in spirit to the original APS genetic loop.

The final sequence is read from `result.final_solution.variable_values` using
the `sequence_node_id` returned by `model.build_mg_program(...)`. Each candidate
evaluated by OptAgent calls the external MG scorer with the current sequence
value, so the reported best sequence and persisted output tables come from the
solver's final variable assignment.
